# Threads 工具鏈改進研究 — AK-Threads-Booster 競品分析

> **來源**：[akseolabs-seo/AK-Threads-Booster](https://github.com/akseolabs-seo/AK-Threads-booster)
> **分析日期**：2026-05-10
> **目的**：萃取值得借鑑的設計，作為自有 Threads 工具鏈改進的參考

---

## 1. 現有工具鏈 vs AK-Threads-Booster

### 1.1 功能覆蓋矩陣

| 功能領域 | 我方工具 | AK 對應模組 | 差距判定 |
|----------|---------|------------|---------|
| 發文 CRUD | `threads` CLI（完整 API） | 無（純顧問） | ✅ 我方優勢 |
| 貼文抓取 | `fetch_threads_post.py`（A-E 分類） | `/refresh`（API + Chrome） | ≈ 持平 |
| 選角度 | `threads-angle-gate`（蘇格拉底對話） | 無獨立機制 | ✅ 我方優勢 |
| 選題推薦 | ❌ 無 | `/topics`（留言挖掘 + 新鮮度） | ⚠️ 缺口 |
| 起草 | ❌ 無（角度確定後自己寫） | `/draft`（Brand Voice 驅動） | — 設計哲學不同，非缺口 |
| 發文前診斷 | `threads-advisor analyze`（基礎版） | `/analyze`（4 維分析） | ⚠️ 可強化 |
| 績效預測 | ❌ 無 | `/predict`（歷史比較集） | ⚠️ 缺口（低優先） |
| 發文後復盤 | CLI insights，無結構化流程 | `/review`（predict→review 閉環） | ⚠️ 缺口 |
| 品牌聲調 | ❌ 無 | `/voice`（15 維 + 認知層） | — 不急需 |
| 知識庫 | ❌ 無獨立體系 | 3 套（演算法/心理學/AI 味） | ⚠️ 最大缺口 |
| 自我優化 | ❌ 無 | `/optimize`（複利日誌） | — 過度工程化，不採用 |

### 1.2 設計哲學差異

| 維度 | AK | 我方 |
|------|-----|------|
| AI 角色 | 顧問（分析建議，不代寫） | 共創者（對話發現角度，自己寫） |
| 資料依賴 | 重度（tracker.json 是核心） | 輕量，零資料可運作 |
| 冷啟動 | 高成本（setup + voice 要 1-2hr） | 即開即用 |
| 複雜度 | 極高（10+ 衍生檔案、compiled memory） | 簡潔，各工具獨立 |
| 草稿哲學 | AI 生成初稿 → 人修改 | 人寫 → AI 診斷 |

**結論**：不整套採用，萃取知識層和流程設計中有價值的部分。

## 2. 值得借鑑的設計

### 2.1 知識庫體系（最高價值）

AK 有三套知識庫，以下為精華萃取：

#### 2.1.1 演算法知識（algorithm.md）

**紅線區（硬規則 R1-R12）**：

| 編號 | 名稱 | 要點 |
|------|------|------|
| R1 | Engagement Bait | 5 種 bait 類型，ML 偵測覆蓋 25+ 語言 + OCR，累犯加重 |
| R2 | Clickbait | 聳動句式、過量驚嘆號、故意不講重點 |
| R3 | Hook 詐欺 | hook 可以強但不能與正文不一致 |
| R4 | 搬運/低原創 | 相似度 70%+ 警告；需含自己分析/結論/經驗/框架 |
| R5 | 連續同主題 | Meta diversity enforcement，同領域可以，同角度不行 |
| R6 | 低品質外連 | 廣告過多、載入慢、SEO 垃圾頁 |
| R7 | 敏感主題聳動表述 | 政治/健康/財務/性暗示分類處理 |
| R8 | 負面回饋 | 最怕的不是沒互動，是讓不對的人按 Not interested |
| R9 | 主題混雜 | 一篇文只打一個主題中心 |
| R10 | AI 內容未標示 | — |
| R11 | 圖文不一致 | — |
| R12 | 軟性降權（堆疊） | 命中 2 項以上才構成風險 |

**信號區（動態參考 S1-S14，精選）**：

| 編號 | 名稱 | 要點 |
|------|------|------|
| S1 | 私訊分享 | 最強信號，權重是按讚 3-5 倍（引述 Mosseri 2025） |
| S2 | 深度留言 | 5+ 詞留言 = 30 分（按讚 = 1 分） |
| S3 | 停留時間 | 前 1-2 句讓人停、每段有新資訊增量 |
| S6 | 圖文組合 | 圖片貼文互動率比純文字高 ~60%（Buffer 2026） |
| S7 | 語意鄰域 | 系統歸類帳號到語意 neighbourhood，需持續強化 |
| S8 | Trust Graph | 2026 重點：Social → Interest → Trust Graph |
| S14 | Topic Freshness | 帳號內部語意群新鮮度預算 |

> ⚠️ **可信度警告**：部分引述（如 Mosseri 確認、MSI 歷史計分）未附原始來源，可能是 AI 推測。當參考框架用，不要當定論。

**掃描流程**：Round 1 硬紅線 → Round 2 負面回饋預判 → Round 3 正向信號評估

#### 2.1.2 AI 味檢測（ai-detection.md）

**語句層（10 種模式）**：
1. 裝生動的固定句式（「說白了就是」「更離譜的是」）
2. 過度整齊的對比句（前後字數差 ≤5 字）
3. 金句密度過高（連續 2 句高截圖性；全篇 >40%）
4. 表演式轉折（自問自答結構）
5. 反問句鎖結論（段尾反問替代論證）
6. 判斷句太完整（單句含現象+原因+推論）
7. 過度使用連接詞（書面連接詞 ≥3 個）
8. 列舉太工整（各點字數標準差過低）
9. 情緒詞不自然（「令人震驚的是」等標籤詞）
10. 哲理收尾（末句泛化且抽象度高於前文）

**結構層（5 種）**：全篇零讓步、收尾功能堆疊（≥2）、段尾都在收、完美起承轉合、資訊分布均勻

**內容層（5 種）**：數字懸空無來源、只有支持主論的證據、缺具體案例、觀點太中立、知識展示過度

**濃度分級**：低（0-2 確定項）/ 中（3-5）/ 高（6+）

**降 AI 味 7 法**：補具體案例、補判斷錯的地方、補例外、數字加不確定性、留不漂亮的句子、判斷留殘缺感、收尾只講自己怎麼做

> 💡 **應用方向**：可補充到 `humanizer-zh` skill 的檢測清單中。

#### 2.1.3 心理學框架（psychology.md）

**Hook 觸發機制**：
- Information Gap（Loewenstein 倒 U 型 + 鴕鳥效應）
- 數字衝擊（含數字標題分享量 +73%；奇數 > 偶數 20%）
- Pattern Interruption（Von Restorff Effect）
- 負面框架（損失厭惡 2 倍效應，有條件限制）
- Zeigarnik Effect（未完成 > 已完成）
- Peak-End Rule（只記峰值和結尾）
- Hook/Payoff Gap（承諾強但兌現弱最危險）

**留言觸發**：5 大動機（自我表達/歸屬感/糾正衝動/社交驗證/互惠）+ Endowment Effect（留言後產生心理所有權）

**分享動機**：STEPPS 框架 + Dark Social（71% 私人管道分享）+ 四維分享力（DM/公開轉發/身份信號/實用分享）

**信任建立**：Pratfall Effect（能力強又犯小錯最有吸引力）

> 💡 **應用方向**：可融入 `threads-angle-gate` 的角度發現對話中，作為 AI 觀察的參考框架。

### 2.2 流程設計

#### 2.2.1 新鮮度閘門（Freshness Gate）
- 追蹤每個語意群的 `fatigue_risk`（high/medium/low）
- 14 天以上未碰且歷史表現好的主題獲得加分
- 每次選題/起草都要過閘門，超閾值警告
- 記錄到 `threads_freshness.log` 供追溯

**借鑑價值**：輕量版可以只在 `angle-gate` 開始時提醒「你最近 X 天內寫過 N 篇類似主題」。

#### 2.2.2 復盤閉環（Predict → Review → Optimize）
```
預測（發文前估 24hr 績效）
  → 發文
  → 收集實際數據
  → 比對偏差（哪裡猜錯了？）
  → 萃取學習（是選題問題？角度問題？時機問題？）
  → 更新決策規則
```

**借鑑價值**：不需要它的 `/predict` 完整實作，但「發文後簡單復盤 → 記一行學到什麼」的習慣值得建立。

#### 2.2.3 資料信心分級

| 等級 | 可比較貼文數 | 結論強度 |
|------|------------|---------|
| Directional | < 5 | 僅供參考 |
| Weak | 5-9 | 有傾向但信心低 |
| Usable | 10-19 | 可以指引決策 |
| Strong | 20-49 | 可靠基準線 |
| Deep | 50+ | 多維交叉分析有意義 |

**借鑑價值**：任何基於歷史數據的分析都應標注信心等級，防止過度解讀少量數據。

#### 2.2.4 Next Move Engine
三軸狀態評估（演算法 + 受眾心理 + 反 AI）→ 四個必答問題：
1. 必須避免哪些紅線風險？
2. 要強化哪個正向信號？
3. 哪個心理機制讓這個信號合理？
4. 哪個反 AI 質感防止變模板？

三種預設策略：補人格判斷 / 澄清分歧 / 擴散型實用觀點

### 2.3 防護設計

#### 2.3.1 顧問準則（11 條，精選）
- 顧問不是教師，不打分、不糾正、不代寫
- 使用者資料優先，通用基準最後
- 觀察性語言（「你之前這樣做，數據長這樣，供參考」）
- 只在紅線上直接警告
- 資料薄時誠實降級
- 分析 ≠ 重寫（定點建議，不出全文重寫）

#### 2.3.2 Brand Voice 範圍限制
- 只在 `/draft`（生成）中作為創作驅動器
- 所有其他模組（分析、預測、復盤）僅觀察，不重寫使用者內容
- 避免了「AI 把所有內容都拉向同一風格」的問題

## 3. 不採用的部分及原因

| 設計 | 不採用原因 |
|------|-----------|
| `/draft` AI 起草 | 與我方「自己寫」哲學衝突；AI 代寫的文章缺乏個人觸感 |
| `/voice` 15 維聲調分析 | 過度工程化，個人創作者不需要量化自己的聲音 |
| `/optimize` 自我修改規則 | 規則漂移風險高，AI 改自己的 prompt 難以控制品質 |
| compiled memory 機制 | 維護成本太高（hash 驗證、新鮮度檢查、重建流程） |
| FAILSAFE 備份策略 | 對個人用途來說過度防禦，Obsidian 有版本歷史 |
| `tracker.json` 中心化 | 重度資料依賴 = 高冷啟動成本 + 維護負擔 |
| `/panel` 視覺面板 | 功能太淺，不值得獨立維護 |
| `/update` 自動更新 | 不安裝就不需要更新 |

## 4. 可執行的改進方向

### 優先度 A（高價值、低成本）

1. **萃取知識庫內容為素材**
   - 將 algorithm.md、psychology.md、ai-detection.md 存入素材池
   - 經討論消化後，有價值的部分編碼為 AI 知識庫卡片
   - 特別是 AI 味檢測清單，可直接補充 `humanizer-zh` skill

2. **`angle-gate` 加入心理學參考**
   - 在角度發現對話中，AI 可參考 Hook 觸發機制和分享動機框架
   - 不是教使用者「用 Information Gap」，而是在觀察中提到「這個角度可能觸發 X 心理機制」

### 優先度 B（中等價值）

3. **發文前診斷強化**
   - 參考 `/analyze` 的 4 維框架（演算法 + 心理學 + 風格 + AI 味）
   - 強化 `threads-advisor analyze` 或建立獨立診斷 skill
   - 重點：診斷不重寫，定點建議

4. **輕量新鮮度提醒**
   - 在 `angle-gate` 啟動時，快速檢查近期貼文主題
   - 提醒「最近 N 天寫過 X 篇類似主題」
   - 不需要完整的 freshness log，用 `threads` CLI 查詢即可

### 優先度 C（長期考慮）

5. **簡易復盤習慣**
   - 發文 48hr 後，用 `threads` CLI 拉 insights
   - 記一行「學到什麼」到某個追蹤檔
   - 不需要 predict→review 完整閉環

6. **信心分級規範**
   - 任何基於歷史數據的建議，標注基於幾篇資料
   - 可以寫成 `threads-advisor` 的輸出規範
