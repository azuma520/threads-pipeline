# Step 09：可選發文版本輸出

**前置哲學**：本 step 遵守 references/00-philosophy.md 的 5 條原則。

## 目標

根據 user 需求生成不同版本（短版 / 長版 / 多平台）。

## 第一原則：敘事邏輯先、分段後

進 Step 9 第一個動作 = **排敘事邏輯**（不是先想則數）：

- 整體敘事怎麼走（每段承載什麼內容、段間如何遞進、收哪裡）
- 每段內容是否飽滿（不是用字數填滿、是真的有內容推進）
- 段落之間是否有自然斷點

**敘事邏輯排好之後**、分段才會自然成形：
- 500 字內能完整閉合 → 單則
- 有明顯 setup → payoff 結構 → 2 則
- 多個獨立內容 / 步驟 / 案例 → 串文多則

**反例**：從則數推內容（先決定「我要寫 5 則」、再硬塞內容到每則）── 會出現「太薄 / 太細 / 不飽滿」現象、是設計順序反了。0508 acceptance test 走過一次 9 → 5 → 5 飽滿 → 2 飽滿、就是這個反例的修正過程。

## Threads 平台規範參考（必 codify 層）

| 規範 | 來源 | 處理 |
|------|------|------|
| 單則上限 500 字 | Meta 官方 | 硬規格、超過必拆 |
| 串文 vs 單則判斷 | 敘事節奏 | 500 字內能閉合不拆；setup→payoff / 多步驟 / 多案例才拆 |
| 每則一個內容 | 通則 | 一則只承載一個完整內容、能單獨成立有價值 |
| 開頭鉤子 | 通則 | 第一則 / 第一行給衝突 / 問題 / 反常識 / 承諾、不鋪背景 |
| 中段遞進 | 通則 | 每則推進下一則、不重複前面 |
| 結尾收束 | 通則 | 收束要明確、呼籲行動（CTA）要具體非釣魚 |
| 長文 fallback | Meta | 只是「一篇長文章」可考慮 10,000 字 text attachment、不必硬拆串 |

**Source**：codex 0508 上網蒐集（`docs/superpowers/reviews/2026-05-09-thread-design-research-output.md`）。

## 字數參考（半 codify 層、經驗值不是硬值）

第三方經驗值範圍（**沒有 Meta 官方 source**、只能當參考）：
- 首則：120-280 chars
- 中段：180-400 chars
- 結尾：80-220 chars

當 range 看、允許例外。譬如 0508 acceptance final = 2 則 ~480 字飽滿、就違反「短就好」經驗值、但內容撐得起、是有效設計。

## 不 codify（留 user sense 層）

- 語氣、留白、爆點強度
- 固定鉤子公式 / 固定則數 / 每則都要 CTA
- 個人寫作審美

codify 這層會讓內容變平台味、AI 味。

## AI 在乎什麼

版本之間共享主線、但鉤子 / 長度 / 節奏可以微調。**先排敘事邏輯、再決定分段**。

## 為什麼

不同平台 / 不同長度需要不同節奏。譬如 Threads 適合短一點、blog 適合長一點。但主線不能因為長度變化就改 ── 那會變成寫不同篇文章。

## 怎麼跑

1. **排敘事邏輯**（每段承載什麼、段間如何遞進、收哪裡）
2. **檢查每段內容飽滿度**（飽滿不飽滿、能不能單獨成立）
3. **依平台規範決定分段**（500 字斷點、敘事斷點）
4. **產出每個版本 + surface 砍了什麼**（訪談原則對齊）

**訪談原則對齊**（呼應 spec subagent validation 問題 1.2）：不同版本 surface 給 user 時、附「**砍了什麼 / 為什麼**」邀請 user 用刪除法判斷：

「**短版我這樣砍：拿掉 X 段（理由：對主線只是補強、可砍）、留 Y / Z（理由：主線骨架不能砍）。你看這樣 OK 嗎？**」

如果只是 user 已 settle 不需再校準（譬如自動產短版發 Threads），可跳過 surface 直接出版本。但**預設走訪談原則**。

## sense 層

- 哪些段可砍 / 不可砍 ── 模型 sense
- 不同平台節奏調整 ── 模型 sense
- 字數參考值套不套 ── 模型 sense + user 校準
- 串文則數最終決定 ── 模型 sense + user 校準（不是固定公式）

## Gate（結束前 / 多版本完成）

- [ ] **敘事邏輯先排好再分段**（不是從則數推內容）
- [ ] 每個版本主線一致（不變主題）
- [ ] 每段內容飽滿、不是用字數填滿
- [ ] 平台規範通則符合（500 字 / 開頭鉤子 / 中段遞進 / 結尾收束）
- [ ] 預設走訪談原則 surface「砍了什麼 / 為什麼」（除非 user 已 settle 跳過）
