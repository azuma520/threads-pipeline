# 用戶角色設定資料 — 範本

> **這是範本、不是實際 profile**。複製此檔成 `02-user-profile.md`（同目錄）後填入你自己的資料。
> 實際 `02-user-profile.md` 已 gitignore、不會推上 GitHub。
>
> 此文件 codify 用戶的**固定身份背景與寫作核心**（Layer 1）。
> 供 `threads-write-flow` skill 在寫文章前載入、作為 agent 寫稿的基底參考。
> **變動部分**（每篇的角色設定 + 個人觀察 + 經驗）由 Step 1 / 2 / 2.5 per-piece 從 dump + 訪談抓取，不在此 codify。

---

## 0. 三層模型（概念框架、不用改）

```
Layer 1 — 固定（本文件、跨多篇用）
├─ 內核
├─ 工作 / 身份背景
├─ 主要受眾
├─ 長期方向 + 策略 + 硬約束
├─ 紅線（拒絕的角色預設）
└─ 表達方式偏好 + 草稿品質下限

Layer 2 — 每篇不同（從 dump / 訪談抓）
├─ 這篇的角色設定（身份/視角/思維/背景 4 維）
├─ 個人經驗（事件層）
└─ 個人觀察 / 心得 / 判斷（重量層）

Layer 3 — 自然 derive
└─ 文風 / 用詞 / 切入點
```

## 7. 角色設定 — 4 維 schema + N 樣子實例參照

### 7.1 4 維 schema（描述任何角色的結構、Step 2 抓取時用）

每篇都用這 4 維 surface 給 user verify：

- **身份**：這篇的我是誰
- **視角**：怎麼看這件事
- **思維**：思考方式
- **背景**：context

### 7.2 N 樣子實例（你常用的 4 維組合、參照用）

從你過去 5-10 篇代表作 surface 2-5 種你常用的「角色樣子」。每個樣子用 4 維填出。

樣子是參考、**不是 enum**。實際抓到的可能是混合、或新樣子 ── agent 用 4 維 surface 給 user verify。

#### 樣子 A：`<樣子名稱>`

- **代表題材**：`<題材類型>`
- **身份**：`<身份描述>`
- **視角**：`<視角描述>`
- **思維**：`<思維方式>`
- **背景**：`<context>`
- **文筆**：`<文筆代表詞>`
- **代表作**：`<代表貼文 / 篇章>`

#### 樣子 B：`<樣子名稱>`

- ...（同 A 結構）

#### 樣子 C：`<樣子名稱>`

- ...

（依需求加 D / E）

### 7.3 重點

- 同一個 user、不同樣子、per-piece 切
- 樣子不一定靜態 ── 可以有「角色 arc」（譬如「過去的我 → 現在的我」）
- agent 抓 4 維後對照樣子：「像哪個 / 混合 / 新樣子？」── 給 user 用刪除法 verify

## 8. 維護

此文件描述用戶的**固定層**。應該很少變動。

可能會變的時機：
- 用戶工作 / 身份大變化
- 受眾結構改變
- 內核發現新的 / 重新 reframe（很少、但可能）

**更新規則**：
- agent 觀察到值得補 / 修的面向 ── 可以主動提議跟用戶討論優化
- 實際更新由用戶拍板 ── agent 不自動寫
