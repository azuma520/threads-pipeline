## 主線 = 角色設定 + 4 件事

「主線」包含兩層：

| 層 | 內容 | 對應 spec |
|---|---|---|
| **件事 0**：角色設定 4 維 | 身份 / 視角 / 思維 / 背景 | spec「這篇的角色設定」|
| **件事 1-4**：事件層 + 重量層 | 核心問題 / 誤解 / 轉折 / 判斷 | spec「個人經驗 + 個人觀察 / 心得」|

3 件事 view（spec 視角）：
- **角色設定（4 維）** = 件事 0
- **個人經驗（事件層）** = 件事 1 + 件事 2 + 件事 3（核心問題 / 誤解 / 轉折）
- **個人觀察 / 心得 / 判斷（重量層）** = 件事 4（判斷）

## 件事 0：角色設定 4 維

這篇文章的「我」是誰、怎麼看、怎麼思考、在什麼 context ── 4 維必須抓對、否則後面 step 全歪。

| 維度 | 抓什麼 | 例子 |
|---|---|---|
| **身份** | 這篇的我是誰 | 「一年前剛接觸行銷的我」/ 「正在做某事的我」/ 「父親」 |
| **視角** | 怎麼看這件事 | 自我回顧 / 痛點→動手 / 借第三方觀點 / 日常→借喻 |
| **思維** | 思考方式 | 問題驅動 / 直覺串接 / 聯想式 / 漸進 |
| **背景** | context | 跨領域成長某段 / 正在做的當下 / 家庭旅行場景 |

**怎麼抓**：從 dump + Layer 1（profile Section 7 樣子實例）對位、surface 假設給 user 用刪除法 verify。

「**我聽下來這篇的我像「樣子 A（從接觸新領域到做出成果者）」── 身份是 X、視角是 Y、思維是 Z、context 是 W、你看對不對？**」

**對位 profile Section 7 樣子實例**：抓完 4 維後對位、surface「這篇看起來像樣子 A？還是 B？或哪個混合？」── user 用刪除法選或修；如四個樣子都不像、surface「這像新樣子、你怎麼描述？」給 user 確認、**不擅自寫進 profile.md**。

## 件事 1-4：原本的 4 件事架構（保留）

抓出 user 真正想講的東西，不是 user 表面講的。**4 件事必須綁原文錨點**（spec Patch #7）：

| 件事 | 內容 | 錨點需求 |
|---|---|---|
| 1 | **核心問題**（這篇文章在問什麼 / 在解決什麼） | 原文 quote / 場景 / 事件 |
| 2 | **使用者原本的想法或誤解**（user 一開始怎麼想） | 原文 quote / 場景 / 事件 |
| 3 | **轉折點**（哪裡開始覺得不對、哪裡重新理解） | 原文 quote / 場景 / 事件 |
| 4 | **可能想留下的判斷**（user 看懂了什麼） | 原文 quote / 場景 / 事件 |

**為什麼必須綁錨點**：4 件事本身是抽象判斷（tell 形式）。如果 AI 只抓抽象判斷不綁錨點，後面 Step 5 / Step 7 想 show 也沒具體素材可 show ── 錨點是 show 的素材 source。

**錨點可以是**：(1) user 原話 quote、(2) 具體場景描述、(3) user 提到的事件 ── 至少其中一種。

**沒有就沒有**：如果某件事在原始素材中找不到任何錨點、surface 給 user 並 flag「**這條我沒抓到出處、是不是你還沒講？**」── 不要自己編、呼應 ripple #3。

**真實 dump 觸發頻率提示**：真實 dump（工作日報式 / 多線索並列）容易在**件事 2（誤解）/ 件事 4（判斷）**大量觸發「沒有就沒有」── 0508 acceptance test 兩條都觸發。AI 不要因為觸發次數多而質疑自己「是不是該硬補」── 觸發本身是 sense 工作的證據、不是缺陷。

## 為什麼

原始素材通常會有表層敘事（發生什麼事）+ 深層觸動（為什麼這件事重要）。AI 的任務是把深層觸動 surface 到表層、變成 user 可以校準的 first draft 主線。錨點讓「first draft」落在具體素材上、user 校準時有具體 reference 可以判斷對 / 不對（呼應刪除法）。

## 怎麼跑

AI 從原始素材中抓出 4 件事 + 每件事的錨點。把結果用訪談語氣輸出（呼應 10.6）：

「**這是我聽下來的版本：核心問題是 X（從你說的這句：『...』）、誤解是 Y（從這個場景：『...』）、轉折是 Z（...）、判斷是 W（...）── 你看對不對？**」

→ user 用刪除法判斷每件事跟錨點對 / 不對。

## 多線索 dump 的下注（真實 dump 常見）

真實 dump 常常是「工作日報式」── 多段執行項目 + 數據、不是一條 explicit narrative。AI 要：

1. **先 sense 哪條線最有敘事節奏**（譬如：6 段執行項目中、哪一條能撐起「誤解 → 轉折 → 判斷」結構）
2. **明確 surface 下注**：「**我下注 X 當主軸（理由：...）、其他段先擱置 / 當支撐**」── 不是 silent 篩選
3. **user 用刪除法駁回**：user 看到下注理由可以快速判斷對 / 不對、reframe 主軸成本低

**反例**（0508 acceptance 走過）：AI 機械抓 4 件事、下注「248 黃檸檬 → KW Cannibalization」、user 完全駁、reframe 主軸「AI 一天可處理多少 SEO 工作量」+ 副主線「站級稽核蹭 SEO 大神 skill 流量」── 真實 dump 多線索、機械抓 4 件事會錯軸。

**何時用**：dump 包含多段獨立內容（不只一個事件 / 一個敘事節奏）、AI 要選一條當主軸時觸發。

## sense 層

- AI 怎麼從表層敘事抓深層觸動 ── 全交模型 sense
- 哪句 quote 最能代表這件事 ── 全交模型 sense
- 何時動用「沒有就沒有」flag（找不到錨點 → surface） ── 模型 sense
